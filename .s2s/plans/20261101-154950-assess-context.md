## Overview

BR-011 and NFR-017 say a prompt instruction is not a control. Excluded material must be *absent*, provably, from model input and from every later path. ARCH-069 enforces this in two layers:
1. Capture-time minimisation in the worker. The snapshot is the permitted projection only.
2. One pure function, `assemble_context(snapshot, frozen_policy) -> ContextBundle`. Its result type cannot be constructed anywhere else, and it is the only input the discussion LLM adapter accepts.

This plan builds both layers, Part A rendering (REQ-094 part A, BR-009), server-side item references (REQ-095) and the REQ-101 input glue. It also builds the verification asset: a canary fixture matrix covering every forbidden field × question type × assignment shape, checked against the stored snapshot plaintext, the assembled bundle, the exact bytes captured at a recording LLMProvider, logs at every level, QueryTrace and the audit store. These are the repo's first shared recording LLMProvider / VectorStoreProvider test doubles.

## Design Notes

- **Module layout and import contracts.**
  - `vektra_assess/context/capture/` (worker only: capture_snapshot, attempt selection, disclosure policy, file intake) may import `vektra_assess.moodle` and the parser client. Import-linter makes `vektra_assess.context.capture` importable only from `vektra_assess.worker.*` and the package itself (COMP-005 split).
  - `vektra_assess/context/snapshot.py` (models, canonical JSON, hash), `bundle.py` (ContextBundle type), `_assembly.py` (the only constructor), `assemble.py`, `part_a.py`, `references.py` and `payload.py` import nothing from moodle, parser or httpx, so the API process (turns) can import them.
  - Contract (d): `vektra_assess.context._assembly` is forbidden to every module outside `vektra_assess.context`.
- **ContextBundle private constructor.**
  - The class is a frozen Pydantic model with `extra="forbid"`, and `__init__` requires a module-private sentinel held in `_assembly`.
  - `model_construct`, `model_copy`, `model_validate`, `__copy__`/`__deepcopy__` and pickling (`__reduce__`) are overridden to raise.
  - import-linter cannot see call sites, so an AST test scans `vektra-*/src` and `tests/` for `ContextBundle(` and its escape hatches outside `vektra_assess/context/`, with an allowlist of zero.
- **Fail-closed allowlist, not a denylist.**
  - Snapshot and bundle models enumerate permitted fields per item kind. There is no free-form `dict`/`Any`, and no raw Moodle payload is stored.
  - New Moodle data only reaches the model after a model change, which the canary matrix then covers.
  - The disclosure decision is computed BEFORE reading content: `DisclosurePolicy` is derived from the teacher's show_solution flag, combined review options for the student, capability flags (`review_html_filterable`, `rubric_display_settings`) and release state.
  - The readers' outputs are then projected through it. Fields the policy excludes are dropped inside the capture frame, as soon as the reader returns, and are never assigned to a snapshot field, logged or persisted.
- **"Never fetch" versus combined WS responses (honest boundary).**
  - Some Moodle responses carry hidden parts in the same payload as permitted ones. Attempt review HTML is the main case: the service account sees teacher-level rendering.
  - Where a response cannot be split at the source, the guarantee is "held only in the reader/capture stack frame, never persisted, logged or passed on". The structured-only path never forwards html to the sidecar at all.
  - Where `review_html_filterable` is READABLE, the HTML goes to the sidecar sanitizer with a per-review-option removal list (Moodle part classes such as rightanswer, specificfeedback, generalfeedback, outcome). It returns only text.
  - Teacher solution text is a different case: the worker decrypts the teacher config ONLY when show_solution is ON, so the OFF path never fetches it at all.
- **Attempt selection (BR-012).**
  - `select_attempt(attempts, grademethod)` is a pure function. It needs ALL attempts finished/abandoned-ignored, at least one submitted, and every considered attempt fully graded (BR-014) and released (BR-010). Otherwise it returns `NotEligible(reason)`.
  - highest/first/last → the grade-determining attempt, ties under highest → earliest. average → last fully graded and released.
  - Unreadable `attempt_state` or `grading_state` → NotEligible(unreadable). The function never guesses.
- **Snapshot (BR-015).**
  - Contents: labels (display numbering as on the review page), marks/max/state, visible feedback, grade + overall comment (released only), rubric instance + definition version (descriptors only if permitted), review-option and release state, submission text, extracted file text + one REQ-101 status per file, the BR-011 decision record (which exclusions applied, the fallback used), grade-modification timestamps, frozen config flags, Moodle release, schema version.
  - Canonical JSON: sorted keys, marks as decimal strings, NFC-normalised text. `content_hash = sha256(canonical_bytes)`.
  - Encrypted with the plan 2 AEAD helper under the session DEK, with AAD = `session_id|assess_snapshot|schema_version`.
  - Stored in `assess_snapshots(session_id PK, ciphertext, nonce, key_version, content_hash, schema_version, created_at)`. There is no UPDATE grant for any role, and a trigger rejects UPDATE (immutability). DELETE is allowed only to the worker role (rollback, purge).
- **Regrade (BR-008).** `compare_grade(snapshot, current: Readable[GradeReading]) -> RegradeFlag(none|changed(old,new)|withdrawn|unreadable)`. It is pure, called at close by plan 10 for the header, and NEVER refreshes the snapshot. A re-read grade is never written back.
- **Exclusion audit event.**
  - `assess_context_exclusion_applied` carries {session_id, policy_version, excluded_field_set_hash, fallback flags}.
  - The hash is sha256 over the sorted list of excluded field *paths* (e.g. `q3.right_answer`, `solution_text`, `rubric.c2.descriptors`). It contains paths, never values.
  - It uses the plan 2 fail-closed audit writer: a failed write aborts the pre-flight.
- **Part A (REQ-094).** `render_part_a(bundle, session_facts) -> PartA(text, overview_items, at_summary)`. It is deterministic, uses Vektra-shipped Italian strings in `vektra_assess/context/strings.py`, and never calls the LLM.
  - The BR-009 statement is a fixed string with only grade and read-date interpolated.
  - Canonical labels follow REQ-095. Scale grading renders the scale label and never "punti/max". Hidden marks are omitted with a stated reason, and degraded items are flagged.
  - File statuses use the exact REQ-101 strings. The template engine is Jinja2 with autoescape and StrictUndefined.
  - Header-only technical flags stay out of the student-facing text.
- **Item references (REQ-095).** `resolve_reference(bundle, ref) -> Resolved | Ambiguous(<=3 candidates) | NotFound(valid_labels) | Rejected(reason)`.
  - Labels are snapshot-local. Ordinals ("la terza") and keywords are matched against snapshot item titles.
  - Anything shaped like a Moodle id (numeric id, `slot`, `cmid`, `attemptid` keys) is Rejected and audited `assess_item_ref_rejected`.
  - It is used by plan 7 for turns and plan 9 for the picker.
- **Model payload (single serialization path).** `payload.bundle_to_model_payload(bundle) -> list[Message]` is the only function that turns a bundle into model input data. Plan 7's prompt templates wrap it but must not add other data sources. This makes the exact request bytes testable here.
- **RAG.** The bundle has no retrieval field in v1. `vektra_assess.context` holds no VectorStoreProvider reference and forbids importing vektra_index or vektra_core (structural NFR-015 evidence). RAG ON stays out of scope (plan 11 ships the field locked OFF).
- **Logging canary processor.**
  - `vektra_shared/log_safety.py` adds `assess_allowlist_processor`. It is active at ALL levels for loggers under `vektra_assess.*`, keeps only allowlisted keys (event, session_id, site_id, job_id, kind, wsfunction, status, reason_code, duration_ms, size_bytes, count, hash, flag) and replaces everything else with `[dropped]`.
  - It is wired in `vektra_app/main.py configure_structlog()` and in the assess worker entry, ahead of `_pii_redactor`, which stays as is for other packages.
  - The test-only `canary_log_capture` fixture fails on any canary substring anywhere in rendered output.

- [ ] Highest-tie fixture selects the earliest attempt. An average-method quiz selects the last fully graded and released attempt. An unreadable attempt state yields NotEligible and 0 snapshot rows (BR-012, BR-006(b))
- [ ] Snapshot hash recomputed at verify equals the commit hash in 100% of integration sessions. A forced UPDATE is rejected. Tampered ciphertext → Mismatch + 1 audit row. Rollback → 0 rows (BR-015 AC1-4)
- [ ] A regrade between capture and close leaves hash and Part A unchanged and sets `changed(old,new)` (BR-008, BR-015 AC2)
- [ ] For each REQ-101 fixture (per format and question type), the status in Part A matches the expected one. A foreign file id → rejected + audited. 0 file bytes on disk or in DB after capture (checked via tmp dir listing and table scan) (REQ-101 AC1/AC3/AC6)
- [ ] TeX/MathML/code/table fixtures: source preserved verbatim in the assembled context (REQ-101 AC4)
- [ ] References: forged Moodle id or out-of-snapshot label → Rejected + audited. A non-existent label → the fixed text with the valid list. An ambiguous ordinal → ≤ 3 candidates, never a guess (REQ-095 AC3/AC5)
- [ ] import-linter and the AST guard fail on planted violations (contract d, capture split), proven by negative tests in CI

## Testing Approach

- **Pure units**: policy, selection, projection, assembly, Part A and references run hermetically on table-driven inputs built from plan 4's recorded 4.3/5.2 WS responses.
- **Capture end-to-end**: the worker capture runs against MockTransport recordings, a fake parser client (scripted per-status outputs), the plan 2 crypto helpers, and testcontainers Postgres for snapshots and audit rows.
- **Canary matrix**: the central evidence, asserted on bytes and rows, never on self-reported counts or status fields.
- **Live subset**: a `-m moodle` subset repeats capture against the real Docker envs.
- **Golden files**: guard Part A wording.

  - The live subset skips with `BLOCKED: Moodle env unavailable`, never passes.
  - Missing recordings fail.
