## Overview

Provides a reference n8n workflow JSON that demonstrates the periodic document ingestion pattern. Closes the open question on scheduling/orchestration in requirements.md. This is documentation work, not code.

## Design Notes

The workflow JSON must use n8n v1.x node types. The pattern: HTTP Request (check document hash via SHA-256) → IF (skip if hash matches existing) → HTTP Request (POST /ingest) → Wait/Loop (poll GET /ingest/jobs/{id}/status) → notify on success or failure.

## Tasks

- [x] Create `docs/workflows/` directory
- [x] Write n8n workflow JSON `docs/workflows/periodic-ingest.json`: nodes for (1) schedule trigger (cron), (2) list source files (HTTP or filesystem), (3) compute SHA-256 of each file, (4) check if hash exists (GET /stats or HEAD on document endpoint), (5) skip if exists, (6) POST /ingest with file, (7) poll GET /ingest/jobs/{id}/status until INDEXED or FAILED (with retry and timeout), (8) send notification on completion
