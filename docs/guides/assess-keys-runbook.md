# Assess keys: backup, restore drill, KEK re-wrap, hand-off re-seal

Operator runbook for the assessment discussion feature (`VEKTRA_ASSESS_ENABLED=true`). Key
purposes and the rotation order are in [configuration](../reference/configuration.md#assess-key-purposes-and-rotation).

## File ownership on Linux

The assess containers run as uid 1000 and refuse a secret file owned by any other user (or not by
root), or with a mode looser than 0440. Docker Compose on a Linux engine does not remap the owner of
a file secret, so after `make assess-keys` run `sudo chown -R 1000:1000 secrets/assess` (Docker
Desktop on macOS maps ownership for you). The CI job does exactly this.

## Back up the keys, separately from the database

The database holds only ciphertext. The keys that open it live in `secrets/assess/` (generated by
`make assess-keys`). Back the directory up **offline and apart from every database dump**: a dump
plus the keys is the whole exam record, so the two must never travel together.

**A lost `assess_kek` means every snapshot and turn of every session is unrecoverable.** There is
no fallback and no second copy in the database. The same is true, for transcripts, of
`assess_transcript_kek`, and for teacher configuration, of `assess_teacher_config_private`.

## Restore drill (do it before you rely on it)

1. Restore the database dump into a scratch Postgres.
2. Mount the backed-up `secrets/assess/` into a scratch worker (`vektra-assess-worker`).
3. Run the rewrap helpers with the old kid as the source: they unwrap every DEK, so a missing or
   wrong key fails loudly here instead of during an incident.
4. Compare: the number of sessions whose DEK unwrapped must equal `SELECT count(*) FROM
   assess_session_keys WHERE kek_wrapped IS NOT NULL`.

## Re-wrap the KEK

1. Add a new kid to `assess_kek`, make it `active`, redeploy the worker.
2. Run `rewrap_session_keys(conn, keyring, from_kid)` in a loop (commit between batches) until it
   returns 0. Do the same with `rewrap_transcript_deks` for `assess_transcript_kek`, and with
   `reseal_teacher_configs(conn, old_private, new_public)` when the teacher-config key pair
   rotates (each returns the rows still on the old key, never the rows it just touched).
3. Only now remove the old kid from the keyring.

## Re-seal the hand-off

The API's hand-off key pair protects the DEK of each LIVE session. To rotate it, add the new pair
under a new kid, deploy the API with the new private key, then run
`reseal_handoffs(conn, kek_keyring, new_api_pub, new_kid)` on the worker until it returns 0. A
session that closes meanwhile loses its hand-off row (the close deletes it), so the helper skips it.

## Shredding

`shred_session` and `shred_transcript` null the wrapped DEK first, then delete the ciphertext rows
and return per-table counts. They refuse a session that is not CLOSED. Verify a purge by counting
rows, not by trusting a status.
