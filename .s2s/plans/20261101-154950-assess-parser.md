## Overview

All untrusted input of the discussion feature — student submission files (PDF, DOCX, ODT, text and
source code) and the quiz review HTML read from Moodle — is parsed in `vektra-assess-parser`: a
separate Compose service built from the same image, with no network, no secrets, a read-only root, a
non-root user and hard memory/pid/CPU limits. Each item is parsed in a fresh child process under
rlimits and killed on timeout. The only way in is a unix socket on a volume mounted into the worker and
the sidecar, never into the API.

The output is text plus exactly one status from the REQ-101 vocabulary. The worker-side client treats
that output as untrusted (size cap, strict UTF-8, status enum). If the sidecar is not running, the
feature is unavailable: there is **no degraded in-process mode** (ARCH-066), pre-flight rolls back and
the setup check fails.

This plan does not decide which files belong to a submission (ownership and the 10-file limit are
applied by the caller, plan 20261101-154950-assess-context, over plan 4's WS readers), and it does not
render statuses in Part A or the header (plans 6 and 10). It provides the parsing service, the wire
protocol, the status vocabulary with its canonical Italian labels, the client and the deployment.

## Design Notes

**Reuse vektra_ingest: copy-and-adapt, never import.** ARCH-073 forbids `vektra_ingest` in the
*worker*, not formally in the sidecar, so importing was considered and rejected:
1. import-linter forbids component-to-component imports; `vektra_assess → vektra_ingest` would need a
   carve-out in exactly the package that handles the most hostile input.
2. The semantics differ. `vektra_ingest/extractors/word.py WordExtractor` walks `doc.paragraphs` only
   and drops tables (REQ-101 requires tables preserved, in body order); `extractors/pdf.py
   PdfplumberExtractor` raises `IngestError(ERR-INGEST-003)` for scanned files and has no page cap; both
   log `filename` in warnings (REQ-101/COMP-008 require stderr reduced to codes); both produce
   `DocumentChunk`s for chunking, not a single bounded text with a status.
3. Ingest uses python-docx (lxml) without DTD/entity hardening or zip-bomb guards; ARCH-066 requires
   defusedxml and pre-parse limits.
The sidecar therefore has purpose-built extractors. Only the scanned-PDF heuristic constants
(`_SCAN_THRESHOLD = 100` chars/page over `_SCAN_SAMPLE_PAGES = 5`) are copied, with a provenance comment
pointing at `vektra_ingest/extractors/pdf.py`. Ingest is not modified.

**python-docx is not used.** COMP-008 lists python-docx, but ARCH-066's higher-level rule is "XML is
parsed with defusedxml". DOCX is parsed with `zipfile` + `defusedxml.ElementTree` walking
`word/document.xml` in body order (paragraphs, headings, tables, OMML math text, drawing alt text). This
removes lxml from the hostile path and gives tables in order. PDF uses `pdfminer.six` directly
(pdfplumber is a wrapper over it; dropping the wrapper reduces imported surface and RLIMIT_AS
footprint). This deviation from the COMP-008 dependency list is recorded in Notes.

**Module layout** (`vektra-assess/src/vektra_assess/`):
- `parser_protocol.py` — wire framing, `FileStatus` enum, Italian labels, limits dataclass. Stdlib only.
  Imported by both sides.
- `parser_sidecar/` — `server.py` (asyncio unix server, pool, supervisor), `child.py` (rlimits, stdio
  hygiene, dispatch), `sniff.py` (magic bytes + text heuristic + extension allowlist), `zipguard.py`,
  `pdf.py`, `docx.py`, `odt.py`, `text.py`, `html_review.py` (review-HTML sanitizer), `ping.py`
  (healthcheck client). May import only `vektra_assess.parser_protocol`, stdlib, `pdfminer`,
  `defusedxml`, `html5lib` (import-linter forbidden contract: no `vektra_shared`, no other
  `vektra_assess.*`, no `sqlalchemy`, `asyncpg`, `httpx`, `litellm`, `vektra_ingest`).
- `worker/parser_client.py` — async client; import-linter: only `vektra_assess.worker.*` may import it.
  `vektra_assess.context` receives parse results (or an injected callable) from the worker pre-flight
  handler and never imports the client (ARCH-073 (c)).
- `vektra-app/src/vektra_app/assess_parser.py` — thin entry calling `parser_sidecar.server.main()` plus a
  sys.modules assertion; `docker/entrypoint.sh` target `assess-parser`.

**Process model.** The parent (supervisor) runs the socket server and never parses. A `forkserver`
context preloads the parsing modules; each item runs in a **new child process** (one item per process,
never reused), so no state of one student's file survives into another's (NFR-014). A semaphore of
`VEKTRA_ASSESS_PARSER_POOL` (default 3) caps concurrent children. The child, before reading input:
`RLIMIT_AS` (default 256 MiB, finalised by measurement), `RLIMIT_CPU` (timeout + 1 s), `RLIMIT_CORE`
0, `RLIMIT_NOFILE` 32, `RLIMIT_FSIZE` 0, `prctl(PR_SET_DUMPABLE, 0)`; closes inherited fds; replaces
stderr with a pipe the parent drains and discards (only byte count and exit code are logged); disables
`logging` and `warnings`. Input bytes go in over a pipe, output comes back over a pipe capped at the
response limit. The parent SIGKILLs the child at the wall-clock timeout
(`VEKTRA_ASSESS_PARSER_TIMEOUT_S`, default 10 s per file, set by the burst skeleton in plan 8). Kill,
`MemoryError`, rlimit hit, non-zero exit or oversize output ⇒ `CORRUPT` ("file danneggiato o non
elaborabile"); the parent survives every case.

**Limits checked before parsing** (parent, no parsing): payload ≤ `max_file_bytes` (10 MB) else
`TOO_LARGE` without forking; header JSON schema; extension hint in the allowlist; leading magic bytes.
In the child, before XML: zip guards — entry count ≤ 2 000, declared total uncompressed ≤ 64 MB,
per-entry ratio ≤ 100:1, streamed reads that stop at the cap regardless of declared sizes, no nested
archives opened, overlapping/duplicate entries or bad CRC ⇒ `CORRUPT`. defusedxml with DTDs, entities
and external references forbidden. PDF: page count read first; > 50 pages ⇒ extract pages 1-50 only and
return `READ_PARTIAL(upto_page=50)`.

**Status vocabulary** (`FileStatus`, REQ-101, exactly one per file) and canonical labels:

| Enum | Label (exact, REQ-101) | Emitted by |
|------|------------------------|------------|
| `READ` | letto | sidecar |
| `READ_PARTIAL` | letto parzialmente (fino a pagina N) | sidecar (page cap or char cap) |
| `UNSUPPORTED_FORMAT` | non letto: formato non supportato | sidecar (PPTX, images, DOCM/macro, archives, spreadsheets, media, unknown) |
| `TOO_LARGE` | non letto: troppo grande | sidecar parent (bytes) |
| `NO_TEXT` | non letto: testo non estraibile | sidecar (scanned PDF, empty text layer, undecodable text) |
| `PROTECTED` | non letto: protetto | sidecar (encrypted PDF, OLE-encrypted OOXML, encrypted ODT) |
| `CORRUPT` | non letto: file danneggiato o non elaborabile | sidecar (parse error, timeout, rlimit) and client (protocol violation) |
| `OVER_MAX_FILES` | non letto: oltre il numero massimo di file | caller only (plan 6); the client rejects it if a sidecar ever returns it |

**Wire protocol** (one request per connection, `/run/vektra-assess-parser/parser.sock`): 4-byte
big-endian header length (≤ 4 KiB) + JSON header + payload. Request header:
`{v:1, op: "parse"|"sanitize_html"|"ping", req_id, ext_hint, limits:{max_pages, max_chars, timeout_ms}, payload_len}`.
The original filename is never sent (log hygiene, privacy). Response header:
`{v:1, req_id, status, upto_page, pages_total, chars, code, payload_len}` + UTF-8 text. `ping` with
`deep=true` forks one child under rlimits on an embedded 1-page fixture, proving the pool works, not
only that the socket answers. Up to 32 waiting requests are queued; beyond that the connection is closed
with transport code `BUSY` (not a file status).

**Type detection** (`sniff.py`, own magic bytes, no libmagic in the sidecar): `%PDF-` ⇒ PDF; `PK\x03\x04`
⇒ zip, then `[Content_Types].xml` main part (`wordprocessingml.document.main+xml` ⇒ DOCX;
`macroEnabled` or `vbaProject.bin` ⇒ UNSUPPORTED; presentation/spreadsheet ⇒ UNSUPPORTED) or ODF
`mimetype` first entry (`application/vnd.oasis.opendocument.text` ⇒ ODT, other ODF ⇒ UNSUPPORTED);
`D0 CF 11 E0` (OLE2) with `EncryptionInfo` ⇒ PROTECTED, else UNSUPPORTED (legacy .doc not in the READ
list); image/media/archive signatures ⇒ UNSUPPORTED. Text: no NUL in the first 8 KiB, printable ratio ≥
0.95, extension in the allowlist (txt, md, common source extensions, and html/xml/svg/json read **as
plain text**, never rendered). Decoding: UTF-8 (BOM tolerated), else cp1252 if the heuristic still holds,
else `NO_TEXT`. Extension and magic disagreeing (polyglots) ⇒ the magic wins; a zip-with-PDF-header
polyglot is parsed as PDF only.

**Review-HTML sanitizer** (`html_review.py`, html5lib with the stdlib etree builder, nothing fetched):
`script/style/noscript/iframe/object/embed/link/meta/base` dropped with content; `img` and inline `svg`
⇒ `[immagine non visibile all'assistente]` plus `alt`/`title` text if present; `audio/video` ⇒ a media
placeholder; `a` ⇒ text only (href dropped); TeX delimiters (`\( \)`, `\[ \]`, `$$`) kept verbatim;
`math` (MathML) ⇒ its `annotation[encoding="application/x-tex"]` if present, else the MathML source
serialised as text; `pre`/`code` ⇒ fenced blocks with content verbatim; `table` ⇒ `| a | b |` rows;
**form state preserved as text** (quiz review carries the student's answer there): text `input` ⇒
`[risposta: <value>]`, checked radio/checkbox ⇒ `[x]`, unchecked ⇒ `[ ]`, `select` ⇒ selected option
text, `textarea` ⇒ content. Output NFC-normalised, C0 controls (except `\n`, `\t`) stripped, capped.
The output is plain text; escaping for display remains the renderer's job (plan 10, MathML/SVG XSS
allowlist).

**Worker client** (`worker/parser_client.py`): `parse_file(data: bytes, ext_hint, limits) -> ParseResult`,
`sanitize_html(html: bytes, limits) -> SanitizeResult`, `ping(deep: bool)`. Validation of every
response: header ≤ 4 KiB, strict schema, `req_id` match, `status` ∈ enum and ≠ `OVER_MAX_FILES`,
`upto_page ≤ max_pages`, payload ≤ `max_chars × 4` bytes, strict UTF-8 decode, control-char strip,
`chars` matches the decoded length. Violation ⇒ `CORRUPT` for that file + content-free log code
`assess_parser_protocol_violation`. Socket missing, connect refused, client timeout (sidecar timeout +
queue allowance) or `BUSY` after bounded retries ⇒ `ParserUnavailableError`, which the pre-flight
handler (plan 8) maps to a server-attributable rollback.

## Testing Approach

Unit tests cover framing, labels, sniffing, zip guards, each extractor and the sanitizer in-process
(no fork). Corpus tests run the real server with forkserver children under real rlimits on Linux, so
timeouts, rlimit kills and pid isolation are exercised as in production. Container tests run the built
image under the assess profile and verify the hardening from `docker inspect` and from inside the
container rather than from the compose file alone. Every assertion is on bytes, statuses, pids,
connect counts and measured memory, not on log messages saying "ok".

### Test Infrastructure

- **Required**: Linux (rlimits, `/proc`, forkserver) for corpus tests; Docker with the assess profile for
  container tests; the generated corpus
- **Provided by**: tasks F (corpus generator, tests), E (compose service), plan
  20261101-154950-assess-foundations (assess CI job), plan 20261101-154950-assess-job-loop (worker
  service on which the socket volume is mounted)
- **False-pass guard**: corpus tests `pytest.skip` only off Linux and the CI job asserts 0 skips via
  junit; each corpus case asserts the generator produced the file (size > 0, expected magic) before
  asserting its status, so a missing fixture fails instead of passing; suites registered in
  `tests/test_suite_execution_coverage.py`

> Note (2026-11-02, group B): extractors use defusedxml **SAX** (expat reader with DTD, entities and external refs forbidden) rather than a tree: memory stays flat and the walk stops at the char cap. The client lives at `worker/parser_client.py` as the plan says, so the empty `vektra_assess/parser_client/` stub package from plan 1 was removed and contract (c) now forbids `vektra_assess.worker.parser_client` (not the stub). Defaults chosen where the plan is silent: a zip entry above 64 KiB with ratio > 100:1 is refused (tiny entries may legitimately compress more); legacy OLE `.doc` is `UNSUPPORTED_FORMAT`; NUL-laden or mostly non-printable "text" is `UNSUPPORTED_FORMAT` (binary), undecodable text is `NO_TEXT`; UTF-16 text is accepted only with a BOM; an extensionless file is read as text when the printable heuristic holds; any zip with an encrypted entry is `PROTECTED`. Encrypted PDF fixture carries dummy `/O`/`/U` values: pdfminer reports it through `doc.encryption`/`PDFPasswordIncorrect`, both mapped to `PROTECTED`. The sanitizer keeps TeX spans verbatim and applies HTML whitespace collapsing elsewhere; MathML without a TeX annotation is serialised with local names (no `ns0:` noise).

> Note (2026-11-02, groups C and D): **Process model as built**: parent (asyncio) never parses; `forkserver` context with `vektra_assess.parser_sidecar.child` preloaded and started eagerly; each item a new `Process` (supervised from a thread, SIGKILL by `threading.Timer` at the wall-clock deadline). Input goes over a `Pipe`, the result comes back over a `Pipe` capped at `max_chars*4+4096`; stdout and stderr of the child are one pipe the parent drains and counts (never logged). The child's result is schema-checked by the parent too (the child is not trusted either). **Deep ping** has its own lane (a lock, outside the pool semaphore) so the container healthcheck does not queue behind a burst; it is a 4th concurrent child at most. **Oversize payload** (`payload_len > max_file_bytes`): the parent drains at most 64 MiB so a well-behaved client completes its send, answers `TOO_LARGE` and forks nothing (counter-checked). `BUSY`: header with `status: null, code: "BUSY"`; the client retries 3 times with backoff then raises `ParserUnavailableError`. A reply that is closed with zero bytes is `ParserUnavailableError` (the sidecar died or restarted), a partial reply is a protocol violation (`CORRUPT`). **Setup check**: the item is the existing pluggable `parser_sidecar_running` of plan 4's registry (`register_parser_check(client)`); failure is `MISSING`/`parser_unavailable`, the round trip is logged as `assess_parser_setup_check`. The worker composition root (plan assess-job-loop) must call `register_parser_check`. **Import ceiling** (`vektra_app.assess_parser.assert_import_ceiling`): `sqlalchemy`, `asyncpg`, `httpx`, `litellm`, `vektra_shared.db`, ML, API and other components are forbidden, and any `vektra_assess.*` beyond `parser_protocol`, `parser_sidecar` and the two modules the entry itself needs (`config`, `keys`, for the "holds nothing" proof). `cryptography` is NOT forbidden: pdfminer.six imports it (encrypted PDFs); it holds no key material there. Contracts are now 14: (f) sidecar imports only `parser_protocol`; (g) `vektra_app.main` must not import the parser entry; (c) forbids `vektra_assess.worker.parser_client`. **API guard vs image directory**: the plan asks the API startup to fail if `/run/vektra-assess-parser` exists, but task E has the same image carry that (empty) directory so a named volume initialises 0700 vektra:vektra. Default chosen: the guard fails on a `parser.sock`, on a mount point, or on a non-empty directory at the parser path (the real dormant capability), not on the bare image directory; it runs in step 12 whether assess is enabled or not. The corpus test runs on Linux only (skipped with a reason elsewhere; this dev machine is macOS, so it was run in a `python:3.12-slim` container against the working tree: 62 passed).

> Measurements (2026-11-02; Docker Desktop VM, linux/arm64, image `vektra-parser-test`, parser container 768 MiB / 1.5 cpu / pool 3, RLIMIT_AS 256 MiB): **idle** parser container: supervisor RSS 50-57 MiB + multiprocessing resource tracker 16 MiB + preloaded forkserver 37-43 MiB (about 105-116 MiB of RSS, cgroup `memory.current` 85 MiB at idle because shared pages count once). **Per child** over the 55-item corpus (legit and hostile): VmPeak 60-61 MiB and RSS peak 31-33 MiB for every item that parses normally (50-page PDF included); the huge-stream PDF (700 MiB inflated) runs into RLIMIT_AS at VmPeak 234 MiB / RSS 205 MiB and dies as `CORRUPT` code `memory` in under 0.8 s; zip bombs are refused by the guards at 60 MiB without inflating. **Container `memory.peak`** (cgroup high-water since container start, cgroup is read-only so it cannot be reset): **643 MiB** after 20 rounds of (huge-stream PDF, ratio bomb, 50-page PDF) concurrently and 10 rounds of three huge-stream PDFs concurrently (the true worst case: three children at the limit at once); 0 OOM kills, `OOMKilled` false, budget 768 MiB (84 %). `pids.peak` 13 of 64 after the whole corpus plus the `docker exec` probes. **Ping**: shallow 0.2 ms median, deep (one child forked on the embedded page) 12.9 ms median / 14.8 ms max. **10-file reference submission** (PDF, DOCX, ODT, TXT, MD, two source files, 50-page PDF, latin-1 text, SVG as text) through the worker-side client, all ten concurrently over pool 3: 1.5 s wall including `docker compose exec` overhead (budget 15 s). **Decision**: `RLIMIT_AS` stays at the 256 MiB design default: legit items need about a quarter of it, and the worst case, all three children at the limit, measured 643 MiB against 768 MiB. A deployment that parses very large legitimate files should raise it together with the container `mem_limit` (3 x limit + about 115 MiB idle must stay under the container limit). NFR-020 input: the parser's memory budget per concurrent item is the RLIMIT_AS, 256 MiB, plus 115 MiB shared overhead.
